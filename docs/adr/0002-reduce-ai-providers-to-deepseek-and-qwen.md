# 2. 将 AI 提供商缩减为 DeepSeek 和通义千问 Qwen

- 状态：已接受
- 日期：2026-08-21

## 上下文

应用原本支持 7 个 AI 提供商（DeepSeek、Qwen、OpenAI、Anthropic、OpenAI 兼容、Google AI、Ollama），但经过调研，中国大陆中英翻译场景下 DeepSeek 和 Qwen 是表现最优的国产模型，且其他提供商在大陆不可直接使用或维护成本高。用户希望精简支持范围，降低代码复杂度和维护负担。

## 决策

将 AIProvider 枚举从 7 个 case 缩减为仅保留 deepseek 和 qwen 两个 case，并彻底删除与之相关的死代码，包括自定义 endpoint、自由输入模型名、needsCustomEndpoint/needsCustomModel 属性、模型迁移逻辑以及所有针对被删 provider 的测试和文档引用。

## 后果

正面：代码库大幅简化（删除约 868 行），维护成本降低；用户界面更简洁，不再暴露不必要的配置项；测试覆盖更聚焦于实际支持的提供商。负面：用户若之前使用其他提供商（如 OpenAI、Ollama）将无法继续使用，需迁移到 DeepSeek 或 Qwen；残留的旧数据（如 Keychain 中的 API Key）不会被清理，但也不再被读取，可能造成轻微存储冗余。

## 被拒备选

保留全部 7 个提供商：会增加维护成本，且部分提供商在大陆不可用，不符合用户精简需求。仅隐藏 UI 但保留代码：无法真正降低复杂度，且容易引入配置错误。清理残留旧数据：被拒绝，因为主动清理可能误删用户数据，且残留数据无害，避免过度设计。
