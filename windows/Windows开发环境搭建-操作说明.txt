========================================================================
Windows A 机 — 环境搭建（opencode + cc-suite-cn）+ ELTA Windows 进度与下一步
========================================================================
本文件给你在 Windows 上照着做。目标：以后**在 Windows 上直接写代码/编译/运行**，
不再从 Mac 来回拷贝。
版本标记：随 ELTA 仓库提交一起更新；如与仓库内不一致，以仓库为准。

------------------------------------------------------------
第 0 部分：开始前必须知道的「账号/登录」总览
------------------------------------------------------------
（先看这张表，别装到一半卡在“要不要登录/要不要 key”）

| 组件 | 要不要账号/登录 | 需要什么 | 备注 |
|------|----------------|----------|------|
| opencode 本体 | **不需要账号** | 只要下面某个模型 provider 的凭证 | 用 DeepSeek 自己的 API key 即可，无需 opencode 账号 |
| opencode Zen（官方托管模型） | 需要 opencode 账号 | opencode.ai/auth | **本项目不用它**，忽略 |
| DeepSeek（编排大脑） | 不需要登录网页，只要 **API Key** | platform.deepseek.com 领 key | Mac 上同款；用 /connect 或环境变量配 |
| codebuddy（GLM/Hy4-Preview 网关） | **需要平台账号登录** | 第一次跑时按提示登录 | 不需要额外 key，走登录态 |
| kimi（月之暗面） | 不需要网页登录，只要 **API Key** | MOONSHOT_API_KEY（platform.moonshot.cn） | |
| qwen（阿里通义/百炼） | 不需要网页登录，只要 **API Key** | DASHSCOPE_API_KEY（dashscope.aliyun.com） | |

一句话：
- **opencode 本身不用注册账号**（除非你用它的 opencode Zen，本项目不用）。
- **真正要准备的是各模型的凭证**：DeepSeek key（ELTA 用）、MOONSHOT_API_KEY、DASHSCOPE_API_KEY；
  codebuddy 是**登录态**（第一次跑按提示登录，不用 key）。

安全纪律（务必遵守）：
- Key 只在本机配置，**不要贴进任何对话/聊天/截图**；
- 不要把 key 写进会被 git 提交的文件；
- 配完可用 `setx` 存成用户环境变量（永久生效），取代 Mac 的 ~/.zshrc。


------------------------------------------------------------
第 1 步：装基础工具（Git、Node、终端）
------------------------------------------------------------
在 PowerShell（普通权限即可）里：

  1.1 装 Git
      winget install --id Git.Git -e --source winget
      验证： git --version

  1.2 装 Node.js LTS（opencode 的 npm 装法、以及 cc-suite-cn 都要）
      winget install OpenJS.NodeJS.LTS
      装完**重开终端**，验证： node -v   npm -v

  1.3 终端
      建议 Windows Terminal（一般已内置）或 WezTerm。

  ⚠️ 边缘情况：
     - 若 PowerShell 报“无法加载脚本、禁止运行 .ps1”（npm 会触发）：
         管理员 PowerShell 执行： Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
     - `node/npm/git` 找不到：多半是没重开终端，或 PATH 未刷新；重开即可。
     - 公司网络若有代理，npm 可能超时，需给 npm 配代理（npm config set proxy ...）。
     - Windows 深层 node_modules 可能超 MAX_PATH：管理员执行
         Set-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem' LongPathsEnabled 1
       或 `git config --global core.longpaths true`。


------------------------------------------------------------
第 2 步：安装 opencode + 配置
------------------------------------------------------------
  2.1 安装（三选一，npm 最省事）
      npm install -g opencode-ai
      # 或 scoop install opencode
      # 或 choco install opencode
      验证： opencode --version

      ⚠️ **不要用 WSL**：本项目是 WPF 桌面程序（net8.0-windows），WSL 是 Linux，编不了。
        官方“推荐 WSL”是针对一般项目，不适用于本仓库。用**原生 Windows 版**。

  2.2 全局配置目录（Windows）
      opencode 用 `~/.config/opencode/`，在 Windows 即：
          C:\Users\<你的用户名>\.config\opencode\
      子目录：agents\ commands\ skills\ plugins\ rules\ tools\ themes\
      配置文件：opencode.json / opencode.jsonc / tui.json

  2.3 从 Mac 搬「行为配置」（强烈推荐，做一次）
      **U 盘上已经备好**：`opencode-config-from-mac\`（从 Mac 导出、**已脱敏、无密钥**）。
      把它的**内容**（不是文件夹本身）拷到上面那个 Windows 目录：
          C:\Users\<你的用户名>\.config\opencode\
      然后在该目录执行： npm install   （补插件依赖）
      里面含：agents\ commands\ skills\ rules\ plugins\ nlpm\ scripts\ + opencode.jsonc 等。
      ⚠️ 两点：
        a) 已剔除明文 key（原 opencode.json 里的 VMark token 已移除）；
        b) opencode.jsonc 里有两条 Mac 绝对路径的 skills，需你改/删——
           详见该文件夹内 `README-Windows-搬移说明.txt` 第 4 步。
      注意：**别把明文 key 一起拷**；key 在 Windows 上用 2.4 重新配。

  2.4 配 DeepSeek 的 API Key（二选一）
      方式 A（推荐）：启动 opencode → 输入命令
          /connect
        选 DeepSeek，按提示填 key。
      方式 B：在 opencode.json 里用环境变量占位：
          { "provider": { "deepseek": { "options": { "apiKey": "{env:DEEPSEEK_API_KEY}" } } } }
        然后 PowerShell（设完重开终端）：
          setx DEEPSEEK_API_KEY "你的key"

  ⚠️ 边缘情况：
     - 再次强调：**opencode 不需要单独注册账号**；用 DeepSeek 的 key 即可。
     - 若你 Mac 的配置里 key 是明文内联的，搬到 Windows 时请改成 {env:...} 或 /connect，
       避免明文散落。
     - `opencode` 命令找不到：重开终端；或看 npm 全局目录是否在 PATH：
         npm config get prefix    # 该目录\bin 应在 PATH

第 3 步：安装 cc-suite-cn（多模型代码评审套件）
------------------------------------------------------------
结论先说：**可直接克隆，不用重写**。它是 public 的 Node/JS 仓库，无符号链接、
无 mac 专属二进制，源码里没有写死的 /Users 路径（那串只在历史日志里）。

  3.1 拿代码
      cd C:\
      git clone https://github.com/liuxiaominglove/cc-suite-cn.git
      cd C:\cc-suite-cn
      npm install

  3.2 装 3 个 worker CLI（一次性）
      npm install -g @tencent-ai/codebuddy-code @moonshot-ai/kimi-code @qwen-code/qwen-code
      验证：
        codebuddy --version
        kimi --version
        qwen --version
      （Windows 上命令其实是 .cmd 垫片，能 `where codebuddy` 找到即可。）

  3.3 配 2 个 API key（+ codebuddy 登录）
      - DASHSCOPE_API_KEY（阿里百炼 → Qwen 批判员）
          控制台：https://dashscope.aliyun.com → API-KEY 管理
          PowerShell： setx DASHSCOPE_API_KEY "你的key"
      - MOONSHOT_API_KEY（月之暗面 → Kimi 找 bug）
          控制台：https://platform.moonshot.cn → API Keys
          PowerShell： setx MOONSHOT_API_KEY "你的key"
      - codebuddy（GLM-5.3 + Hy4-Preview 网关）：**不是 key，是登录态**。
          第一次跑 `codebuddy` 时按提示完成登录；之后保持登录即可。
      - 自检（在仓库根目录）：
          node scripts/preflight.mjs
        期望：3 个 CLI ✅ + 2 个 key ✅。

  3.4 Windows 适配点（小改，不是重写）— 逐条确认
      a) `package.json` 的脚本用了 mac 专属写法
             zsh -c 'source ~/.zshrc && node scripts/xxx.mjs'
         Windows 上二选一：
            ① 装 Git Bash 后： bash -lc "node scripts/xxx.mjs"
            ② 直接在 PowerShell： node scripts/xxx.mjs
               （原来放 ~/.zshrc 的环境变量，改用 setx 设到 Windows）
      b) `install.sh` 是 bash 脚本 → 用 Git Bash 执行，或照它内容手动做。
      c) `scripts/preflight.mjs` / `scripts/backends.mjs` 里用
             execSync('command -v "..."')   ← 这是 POSIX shell 语法，Windows 会失败
         目前它会回退成「裸命令名」，但 Node 在 Windows 上用裸名 spawn .cmd 垫片
         可能报 ENOENT。**若报错，需要把探测改成 `where`、或给 spawn 加 shell:true**
         —— 这是一处已知的 Windows 适配点，先记录，遇到再改（改动很小）。
      d) 历史运行记录 `.cc-suite-cn\jobs\*.json`、`verdict-log` 里带 /Users/... 路径，
         不影响运行，可不管/可清理。
      e) `.githooks`（bash）→ Git for Windows 自带 sh，一般能跑；报错就用 Git Bash 手动跑。

  ⚠️ 边缘情况：
     - codebuddy 是**登录态**：换机器/清了用户目录后要重新登录；登录态存在
       `C:\Users\<你>\.codebuddy\`（首次跑时自动生成）。
     - kimi 余额过低可能被限速（官方文档里 mac 版也遇到过），充值即恢复。
     - 两个 key 只对 kimi/qwen 生效；GLM/Hy4-Preview 走 codebuddy 登录，不需要 key。
     - 若 `npm install -g` 报权限错：以管理员开 PowerShell 再装，或设置用户级 prefix。

第 5 步：clone ELTA 仓库并跑起来
------------------------------------------------------------

    git clone https://github.com/liuxiaominglove/elta.git elta
    cd C:\elta
    opencode                     # 进入 opencode，先让它读交接记录

第 8 部分：常见问题 / 边缘情况速查
------------------------------------------------------------
Q: opencode 要注册账号吗？
A: 不用（除非用 opencode Zen）。用 DeepSeek 的 API key 即可。
Q: 各模型都要登录吗？
A: codebuddy 要（登录态）；kimi/qwen 只要 API key（MOONSHOT/DASHSCOPE），不需网页登录；
   DeepSeek 只要 API key。
Q: key 设了但读不到？
A: setx 后**必须重开终端**；确认变量名拼写与 opencode.json 的 {env:...} 一致。
Q: codebuddy 提示未登录？
A: 第一次跑按提示完成登录即可。
Q: npm 全局命令找不到？
A: 重开终端；或把 `npm config get prefix` 对应目录（及其 \bin）加进 PATH。
Q: 编译报 CSxxxx 红字？
A: 全屏截图回传，不要自己改代码。
Q: 需要 WSL 吗？
A: 不需要，也不要用（编不了 WPF）。用原生 Windows。
Q: Mac 和 Windows 的 opencode 会话能同步吗？
A: 不能（各自独立）。仓库 + windows\NOTES.md 是唯一交接来源。
Q: 在 Windows 上改了代码，怎么回到 Mac / 主仓库？
A: Windows 侧 git 只读、不 push。用 U 盘拷回改动文件，或经 Syncthing 同步；
   也可以由 Mac 侧把 Windows 的改动提交/推送。**不要在 Windows 上配 GitHub 凭证。**
Q: cc-suite-cn 会不会因为平台差异跑不起来？
A: 主体是跨平台 Node；已知需微调处见第 3 步 3.4（脚本 shell、command -v / spawn）。
   不是重写，是打补丁。
